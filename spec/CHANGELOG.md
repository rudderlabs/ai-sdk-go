# AI events spec changelog

- **SDK-6799 part 3 — one span per call with the span processor — 2026-11-17.** The SDK span is the one sent when it has an analytics client and its mandatory core fits the span size budget with room for completion timing and status; otherwise OTel exports normally and SDK delivery follows its ordinary path. When RudderStack processors replace an OTel model span, the SDK span is the one kept; if the SDK's own client fails to deliver, that span is lost, as the call's product events are. An inner OTel model-call span with any active SDK call ancestor in the current interaction is dropped by every RudderStack processor using shared coverage across mixed presets and package copies. Manual tool/retrieval/agent middleware do not hide that ancestor, and ancestry stops at the interaction boundary; other processors receive it unchanged. The first direct wrapper call or integration chat span inside an observed, active, recording outer model-call span of the same open interaction adopts its trace/span/parent IDs, fixes the SDK trace (persisted through pause/JSON restore), and sends normally through the SDK path. Later direct calls are children of the adopted ID. A global replacement mark drops the OTel span synchronously at end across processors; there is no owner settlement, held fallback, direct/async owner export, owner timeout or shutdown coupling. SDK-specific limits, such as package copies and map caps, are in each SDK's tracing docs. Filters, batching and tracing-client failures cannot suppress the SDK call. An outer span without an SDK call exports normally; unsampled recording spans remain eligible. Streaming completion after OTel end retains the adopted IDs. Trade-off: RudderStack receives SDK attributes and call timing under OTel IDs, while APM receives the app's original span unchanged. Delayed Agents generation/response starts repoint reservations and unsent children only if none was sent; otherwise retain the reserved ID, clear replacement and export both spans with intact trees. Newer SDK spans in between, ended spans/interactions, other interactions, non-active tracers, model attributes added after start and the bare exporter cannot adopt. Extend `fixtures/span-dedup-v0.1.json` to fixture version 2 with `replaces`, ordered call IDs and delayed-parent cases. Covered OTel descendants retain their span IDs and tree under the SDK owner trace without changing APM spans or user callback inputs; keep an original OTel parent if a child already used it before coverage was committed. An SDK span that replaced or covered an OTel span follows the mandatory-core and ordered shedding rule in [SDK span delivery budget](fixtures/FIXTURE-FORMAT.md#sdk-span-delivery-budget). Spans-off output and event schemas are unchanged.


- **SDK-5688 — benchmarks, load and property tests — 2026-11-16.** Each SDK repo adds overhead benchmarks, a load test and property tests (fuzz tests in Go) of the `_meta`, usage and stream parsers, seeded from the recorded streams in `fixtures/cassettes/examples/`, and documents the measured overhead and limits in `docs/performance.md`. No spec, schema or fixture change.

- **SDK-6111 / SDK-6017 — call-merge, pause and overflow edge cases — 2026-11-16.** Pause delivers pending call events before it captures the segment's totals, so a call or tool recorded during that delivery, by a callback or another thread, counts once, in the paused segment, with its own events, and the paused response keeps the answer captured before delivery unless span filtering skips its source call, in which case the retained span's answer replaces it and is redacted as usual; the final end still refuses such writes, as any write after end. A folded call past `maxCallsPerInteraction` sends `cost_usd`, `credits` and `server_tool_cost_usd` only when every report folded into it had one, and no `error_type` once any of them succeeded. A wrapper report whose credits hook pauses the run while its twin is being selected counts as a new call after resume instead of being dropped; when the hook was called with the twin's usage or larger call count, it is called again for that report alone. A repeat from the same source stays a repeat when its credits hook pauses. An enriching same-source repeat reprices the retained usage, raw model ID, cost and status with the merged agent, purpose and flags; report-supplied credits remain authoritative, and a repeat without new metadata does not run the hook. A span twin of a call with explicit credits does not run the credits hook, unless its usage replaces the twin's. A wrapper report and a span naming a dated ID of the same non-Claude model (`gpt-4o`, `gpt-4o-2024-08-06`) are one call in all three SDKs; another model of the family (`gpt-4o-mini`) never is. `pending_calls` records also preserve `raw_model` in all three SDKs, so JSON restoration keeps the deployed ID for credits pricing (legacy records fall back to `model`). `pending_calls` snapshot records carry an optional boolean `credits_explicit`, so credits a report set itself survive JSON restoration. The call event of calls folded past `maxCallsPerInteraction` that was not sent before the snapshot is written as a `history_only` record with `call_event_pending` and no `last` or `last_ok` marker, and sent after restoration. All SDKs write top-level `primary` and `outcome_hint` as Node objects and read those objects or legacy Python positional lists, preserving model/provider overrides, persistence and outcome ordering across handoff. The three SDKs write `pending_calls` records under the same keys and value types (`matched`, `usage_known`, `started_at` / `ended_at` in epoch milliseconds), so a snapshot written by one restores in another; readers still accept Go's `twin_matched`, `usage_unknown`, RFC 3339 times and `uncredited`, and Python's `started_ns` / `ended_ns`. The Claude Agent SDK adapter orders groups under an alias row by first-seen deployed model ID, then first-seen groups within that ID, with main-loop groups last. Assistant model IDs remain seen across results of the same stream, so later alias rows retain the deployed ID and are not dropped as internal calls. The Claude Agent SDK adapter allocates turn-level extras (1-hour cache writes, service tier, server tool counts) across every deployed-ID row of the main loop, keys resumed provider hints by deployed ID, and reports each dated row of a standalone result under its own ID. It maps a `modelUsage` key or a subagent's `resolvedModel` to a model ID seen in assistant messages only when it is an alias or names the same snapshot, so a subagent result or usage row on another dated ID of the main loop's family keeps its own calls, tokens, cost and credits. Only assistant messages name API model IDs: Python no longer takes them from subagent results or `calls_by_model` keys, which are per `model_usage` key as in Node.js, and `record_claude_result(primary_model=...)` with a family name keeps each dated row's ID and gives `num_turns` to the family's costliest row. Add `pause-segments-v0.1.json`, run by all three SDKs, Claude cases (with a `standalone` input flag) to `audit-normalisation-v0.1.json`, and an explicit-credits case and the `cross_sdk` snapshots, restored by all three SDKs, to `pause-pending-usage-v0.1.json`. Cancelled retained calls cannot acquire credits from an enriching repeat, in the current segment or after either resume path. Legacy pending calls with credits but no credits_explicit marker retain those report-supplied credits; failed-call metadata enrichment never erases a retained amount. Enrichment is visible before a credits hook runs. Each call versions its pricing basis; a hook whose usage or metadata was superseded retries against the current final basis, up to three attempts, then omits credits and reports a credits callback failure rather than retaining a stale amount. Python pending-call restoration preserves first-report order independently of aggregate call counts, and shares an optional one-based report_sequence across all SDKs, keeping late twins from promoting older primary models. Aggregate tracing twins that retain wrapper usage also retain its agent, purpose, fallback and BYOK metadata when pricing credits, regardless of arrival order or resume path. SDK-6942 extends native-field content normalization to mutable and frozen dataclasses, namespaces, objects with inherited slots and dictionaries, and Pydantic v1/v2 models; native bytes are stripped before serializers can stringify or base64-encode them, except inside Go custom-marshaler output with spans off (SDK-6948). With `emit_spans` off, Go calls a value's own `json.Marshaler` or `encoding.TextMarshaler`, as main did, and strips its output as plain data; bytes encoded there as ordinary text, including base64, can reach content (the accepted SDK-6948 trade-off). Other values, and every value with spans on, are walked field by field, while retaining trusted time serialization. Shared native-container cases exercise per-call fields and span attributes/events, including cycles and nested collections in every SDK. Claude message trackers classify exceptions injected by the consumer through throw/athrow as app_error, while provider iteration failures keep provider classification and the original exception is re-raised unchanged. Restored fractional latency_ms and time_to_first_token_ms round half up at event emission in all SDKs, matching fractional call-window timing; shared fractional snapshots cover every writer. Changed BYOK and fallback flags on repeats update retained calls and held events in both directions across resume paths. Pricing revisions reject stale credits callbacks even when prior credits and metadata compare equal. Go isolates every pointer supplied to credits hooks, reprices authoritative twins under shared response IDs, and restores legacy pending report order independently of aggregate call counts; a shared Python snapshot covers the intervening-report variant. Span filtering reindexes retained first-report positions, so twins reported during delivery cannot promote an older primary model. Node normalizes legacy pending records using only the keys the SDK reads, leaving unused extension getters unevaluated. Pricing revisions also protect the twin-merge path: nested or concurrent same-ID enrichment keeps its newer credits when an older authoritative-twin hook returns, for agent, purpose, fallback and BYOK metadata across resume paths. Pause freezes its filtered answer before the first tool-event pass and response redaction, so pending-tool callbacks and redactor-created tools cannot replace response_text unless span filtering skips the frozen answer's source call, when the retained span's answer is selected and redacted as usual; all usage and tool events still join the paused segment. No schema change.

- **SDK-6938 — MCP error messages after response completion — 2026-11-17.** Opt-in `error_message` is attached on failure only after the SDK observes successful response completion: Python after the HTTP/SSE/stdio write itself, Go after the observed write, and Node.js after `transport.send()` resolves. - **SDK-6930 — MCP `traceparent` per W3C — 2026-11-17.** The three SDKs read `trace_id` from an MCP request's `_meta.traceparent` by one rule, W3C Trace Context Level 1: trim Unicode White_Space; lowercase hex only; ignore version `ff` and all-zero trace or parent IDs; version `00` must be exactly 55 characters; a later version may add fields after the flags when the 56th character is `-`. Before, Node and Go accepted a version-`00` value with extra fields, and Python accepted uppercase hex, version `ff` and an all-zero parent ID but refused later-version fields. An ignored `traceparent` falls back to `_meta["com.rudderstack/trace_id"]`, as before. Node now trims opaque wire values (interaction and trace IDs, session IDs, server name and version, resource names, MCP Events IDs and names, identity fields) by Unicode White_Space like Python and Go: a byte order mark is no longer trimmed and U+0085 is. Python trims the same values by Unicode White_Space instead of `str.strip()`, so the information separators U+001C–U+001F are kept. Identity fields are trimmed and capped once in all three, so a 256-character cap that ends in white space keeps it (Node trimmed again). Token scopes keep string entries, each trimmed and capped at 64 characters, drop blank ones and keep at most 100 (Node kept padding and blank scopes; Python turned non-strings into strings). Node drops an MCP Events subscription change whose subscription ID or event name is blank after trimming, as Python and Go do. Go sends the exact registered `prompt_name`, as Node and Python do, instead of trimming and capping it; tool and prompt names and argument keys stay the exact registered names. `fixtures/mcp-traceparent-v0.1.json` pins the `_meta` join keys (`traceparent`, the trace ID fallback and `interaction_id`); `fixtures/mcp-identity-v0.1.json` pins the identity fields and token scopes. Schema: `maxLength: 64` on `auth_method` and `country`; no version change. Node and Python now cap `auth_method` and `country` at 64 code points as labels, as Go already did; the schema and catalog state the cap (`maxLength: 64`), and `fixtures/mcp-identity-v0.1.json` covers them.
