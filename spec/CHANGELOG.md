# AI events spec changelog

Changes to [`ai-events-v0.4.schema.json`](ai-events-v0.4.schema.json), shared byte for byte by the Node.js, Python and Go SDKs.

## 0.4.0 — 2026-10-29

- **SDK-6799 — wrapper and manual spans — 2026-11-13.** Opt-in `emitSpans` (Python `emit_spans`, Go `EmitSpans`) emits one `ai_otel_span` per logical provider wrapper request, independently of `emitLlmCalls`, with GenAI chat attributes and `rudderstack.span_source: "wrapper"`. Manual `span()` operations (`execute_tool`, `retrieval`, `invoke_agent`) use source `manual`, preserve callback return/error behavior and nest through async context; wrappers inherit the same parent. Internal W3C traces persist across pause/resume, independently of application trace links, without an interaction root span. Retained product call events carry the emitted span ID; overflow aggregates omit it. Google AFC has one chat span across all turns, joined only on the final response report. Content acquisition is independent of product publication, masked once; shared normalization strips nested bytes and cyclic edges and stringifies primitive Map keys. Add `emit-spans-v0.1.json` with portable clock, ID and container inputs and extend conformance/pause fixtures. Framework span emission and processor deduplication are outside this part; enabling the processor alongside wrapper spans can produce two spans for a call. No schema version change.

- **SDK-6798 — per-call content in the SDKs — 2026-11-12.** The SDKs now send `call_index` on every `ai_llm_response_received` and, with `emitLlmCalls` and `captureContent`, `input_messages`, `input_truncated`, `output_text` and `output_tool_calls` from all integrations, never carrying inline binary (byte arrays, `data:` URIs and base64 media payloads are removed). Shared fixture scenarios (`per_call_content` in `conformance-v0.4.json`, `perCallContent` cases in `tracing-product-events-v0.1.json`) fix the size-trim, media-part and sanitiser rules; pause snapshots carry an optional `call_sequence` and per-pending-call `call_index`. No schema change.

- **SDK-6819 — submit_feedback — 2026-11-12.** Add `mcp_feedback_submitted`, sent when the agent calls the injected `submit_feedback` tool (opt-in through the SDK's feedback option). Required `feedback_category` (`bug_report`, `feature_request`, `documentation_issue`, `access_issue`, `performance_issue`, `positive_feedback`, `other`); optional `feedback_tool_name` (a tool the server lists), `capability` (with `feature_request` only: one of the owner's known gaps, or `other`) and `feedback_text` (with `captureContent` only: masked, capped at 2,000 characters). Refused calls send nothing. `mcp_capability_requested` and the `request_capability` option are deprecated but keep working; a server cannot enable both tools. Additive: SDK `specVersion` stays `0.4.0`.

- **SDK-6818 — structured content masking — 2026-11-12.** With content capture on, recursively mask every string in object and array content attributes at span, event, resource, instrumentation scope and link locations, keeping non-string leaves without mutating caller spans. If any nested string is withheld by redaction, drop the whole attribute; the tracing conformance fixture now accepts nested JSON attribute values and covers this behavior.

- **SDK-6802 — tracing content privacy — 2026-11-12.** With content capture off, remove span status descriptions and `exception.message` / `exception.stacktrace` from exception events, keeping status codes, `exception.type` and other exception attributes. Apply known content-key stripping (capture off), masking/redaction (capture on) and always-stripped keys (including request/HTTP headers) to resource, instrumentation scope and link attributes as well as span and event attributes; app-defined custom attributes remain outside this policy. The tracing conformance fixture now covers both rules. Spec documentation only; no schema change.

- **SDK-6797 — per-call content and wrapper spans — 2026-11-11.** Add optional `call_index` (integer >= 1, the 1-based call order within its interaction, always allowed and not content) and `span_id` (this call's `ai_otel_span` span ID when `emitSpans` is enabled, absent otherwise) to `ai_llm_response_received`. With both `emitLlmCalls` and `captureContent`, add `input_messages` (the full system prompt, history and tool results sent on the call, in the OpenTelemetry GenAI `gen_ai.input.messages` shape: an array of `{role, parts: [{type, content|...}]}`), `input_truncated` (true when messages were dropped or shortened), `output_text` and `output_tool_calls` (an array of `{name, arguments?}`, with required string `name` and any JSON arguments; GenAI-compatible naming where it does not conflict). Content is opt-in: treat as personal data and mask like `prompt_text`. Past the size cap, drop the oldest messages after the system prompt first.
  The new SDK option `emitSpans` (Python `emit_spans`, Go `EmitSpans`) makes wrappers and framework integrations emit `ai_otel_span` per model call, tool, retrieval and agent step, with GenAI semantic-convention attributes (`gen_ai.operation.name`: `chat`, `execute_tool`, `retrieval`, `invoke_agent`) plus `rudderstack.interaction_id`. Span content attributes follow `captureContent`. This is a spec contract for later SDK implementation. The changes are additive: no schema version bump; SDK `specVersion` stays `0.4.0`, and `ai_otel_span` schema v0.1 and its required fields remain unchanged.

- **SDK-6801 — app-sent classifications — 2026-11-11.** `ai_interaction_classified` may also come from the app through `trackClassification` (Python `track_classification`, Go `TrackClassification`) for any interaction it chooses, including errored, cancelled or finished ones. Description only: properties, label rules and the hook are unchanged.

- **Normalization and status parity — 2026-11-05.** Custom-property guards snake-case acronym and lowercase/digit boundaries, lowercase, collapse every non-alphanumeric run to one underscore and trim surrounding underscores; warnings name each original content key once. Claude identities repeatedly remove inference profiles (`us.`, `us-gov.`, `eu.`, `apac.`, `jp.`, `au.`, `in.`, `global.`), `anthropic.`, Bedrock `-vN:N`/`:N`, Vertex `@revision`, and trailing eight-digit dates, then lowercase. Router vendor paths are removed for Claude IDs. Keep `-latest` and other aliases; non-Claude IDs stay byte-unchanged. Emit and group/deduplicate by the canonical identity, but price and invoke credit hooks with raw IDs. Migration: uppercase and stacked-suffix Claude values change, equivalent usage rows merge, and distinct aliases/families remain separate; update telemetry queries accordingly. Latest provider/finish hints supersede earlier hints; generic `app_error` preserves a current classification, while explicit app outcomes retain their precedence. Shared input/output cases are in `fixtures/audit-normalisation-v0.1.json`.

- **Production audit correction — 2026-11-05.** The client v0.2 response status enum accepts `incomplete` for a rendered partial terminal answer, matching the server. Schema filenames and emitted specVersion remain unchanged, following the additive client-schema precedent.

- **SDK-5989 — one-shot and client events.** Explicit one-shot interactions use the interaction ID as the required conversation ID when no thread exists. Chat defaults retain a separate conversation ID. Web and mobile client events cover prompt metadata, actionable suggestions and reversion, scoped feedback and preset reasons, snake_case export destinations, conversation pin/share, agent and mode selection, assistant entry/close, limits and declared client tool outcomes.
- **SDK-5990 — server fields.** Answers support `blocked` with `block_reason`, app-set confidence, credits, agent versions, variants and compaction counts. Declared tools support denied outcomes, MCP server names and result sizes. Per-call events include measured timing, credits, purpose, fallback and BYOK flags; usage entries group by purpose. Provider context-window errors use `context_limit`; classifier outcomes include `unsupported`. App-sent `ai_limit_reached` describes customer usage limits.
- **SDK-5992 — sampling.** Optional per-event rates stamp kept server events with `sample_rate`, including `ai_limit_reached`. The shared SHA-256 interaction draw keeps decisions consistent across events and segments. Answers remain unsampled by default; the shared sampling fixture fixes cross-SDK decisions.
- **SDK-5991 — pause/resume.** Each paused or final answer segment shares the interaction ID. Paused segments carry `pause_reason`; final segments carry `pause_count` and `total_paused_ms`. JSON snapshots preserve scope, deduplication and pending usage across restarts. Optional `ai_task_started` reports new background runs once and is not repeated on resume.

The server schema and conformance fixture are v0.4; SDKs emit specVersion 0.4.0. The migration checker accepts both 0.3.0 and 0.4.0 captures. The client schema remains v0.2, matching the v0.3 release precedent. “Since v0.4” annotations remain: the v0.3 release did not remove version annotations.
