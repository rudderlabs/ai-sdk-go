# AI events spec changelog

- **SDK-6911 — structured-output tools — 2026-11-16.** A request forcing exactly one named tool marks matching response tool calls as structured-output candidates. Only at final End, exclude a candidate with no tool result and no already emitted tool event from tool counts, breakdowns and unknown-outcome declared events; retain model calls and tokens. OpenAI Chat/Responses, Anthropic, Bedrock Converse, Gemini ANY with one allowed function, and Vercel named tool choices share this rule, without library markers. Pause retains candidates (optional `structured_candidate`, `result_seen` and `tool_event_emitted` pending-tool snapshot fields) and defers unknown events, allowing results after resume. Native response formats are unchanged. Spans follow the rule when request-choice and tool-message attributes exist; absent request choice is a documented limit. Exclusions have a debug reason, not a new product field. Language-neutral recognition, lifecycle, provider wire payloads and span cases are in `fixtures/structured-output-v0.1.json`; existing recorded fixtures are unchanged. No schema version change.

- **SDK-6799 part 2 — 2026-11-14.** Node framework integrations emit
  `ai_otel_span` with `rudderstack.span_source: integration` alongside the existing
  `wrapper` and `manual` sources. LangChain parent runs include retrieval spans;
  Agents SDK parent IDs preserve nested agents, handoffs and tools; Claude
  Task/Agent launches parent subagent models/tools through `parent_tool_use_id`;
  Vercel middleware emits model-step spans, without unobservable local tool
  execution spans. Integration model contexts own model spans and wrapped calls
  enrich/join them, avoiding duplicate model spans. Content follows
  `captureContent`; spans-off product bytes and emission checkpoints match recorded
  main. The language-neutral `integration-spans-v0.1.json` fixes parent expectations
  and permits later thread-pool/goroutine cases. Vercel is Node-only; Python supports
  the other three framework integrations; Go has none. Additive, no schema or
  product spec version bump.

## 0.4.0 — 2026-10-29

- **SDK-6886 follow-up — more User-Agent clients — 2026-11-16.** The built-in User-Agent fallback names four more clients seen in production, each as its own initialize clientInfo name: `Claude-User` → `Anthropic/ClaudeAI`, `codex-mcp-client/` → `codex-mcp-client`, `copilot-cli/` → `copilot-cli` and `Devin-MCP-Client/` → `rmcp`. - **SDK-6885 — calling model on `mcp_tool_called` — 2026-11-16.** Add optional `caller_model` and `caller_model_source` (`client_metadata`) to `mcp_tool_called`. Only `model` is read, from a `tools/call` request's `_meta["io.modelcontextprotocol/aiInvocation"]` (SEP-2817, draft), then `_meta["x-codex-turn-metadata"]` (Codex CLI); the first non-blank string wins. After trimming Unicode White_Space, keep at most 64 characters matching `^([A-Za-z0-9][A-Za-z0-9_-]*/)?[A-Za-z0-9][A-Za-z0-9._:+-]*(@[0-9]+)?$` (at most one optional `provider/` segment, with no dots or colons in the provider). Otherwise, or for ASCII case-insensitive `arn:` prefixes or endings `.gguf`, `.ggml`, `.bin`, `.safetensors`, `.onnx`, `.pt`, `.pth`, `.ckpt`, `.tflite`, `.mlmodel`, `.mlpackage`, send `unknown`, never cut or fall through to a later key. Multi-segment IDs such as `accounts/fireworks/models/x` and LiteLLM's `openrouter/anthropic/x` lose their name as `unknown`, the privacy-safe direction. Known gap: an extensionless one-slash relative path such as `models/demo` is indistinguishable from provider/model and is kept. Nothing else from `_meta` is copied. The model is client-asserted and unverified. Add `fixtures/mcp-caller-model-v0.1.json`. Additive; no schema version change.

- **SDK-6888 — per-feature content capture — 2026-11-16.** `captureContent` (Python `capture_content`, Go `ContentCapture` beside the boolean `CaptureContent`) takes a boolean, as before, or an object at every level: global, interaction or task, MCP wrapper and tracing exporter. Keys: `default`, `answerText` (`prompt_text`, `response_text`), `llmCalls` (per-call content), `spans` (`messages`, `toolCalls`, `http`), `feedbackText` (`feedback_text`, `capability_detail`), `scoreExplanation`, `intentSummary`, `callReason` and `errorMessage`. Per key, a level's key beats its `default`, an unset key falls through to the level above, and nothing set is off; a boolean is `{ default: b }`, so boolean settings behave as before. `intentSummary` and `spans.http` count only where set: `default` and booleans never change them. `spans.http` keeps `url.path` and full URLs without the query string; `url.query`, user agents, client addresses and headers stay stripped. Add `capture-policy-v0.1.json` (resolution, invalid values and span kinds), object-policy scenarios in `conformance-v0.4.json`, `--capture-policy` cases in `migration-check-v0.1.json`, and `toolCallAttributeKeys` / `httpAttributeKeys` in `span-content-keys-v0.1.json`. No schema change.

- **SDK-6898 — span mapping gaps — 2026-11-16.** Map `gen_ai.usage.cache_write.input_tokens` before cache-creation aliases, without double counting and with cache-write pricing. Normalize only the four evidenced API provider IDs (`anthropic.messages`, `openai.chat`, `openai.responses`, `google.generative-ai`); preserve dotted semantic-convention provider names. Fall back to singular finish reasons with case-insensitive enum-suffix normalization; count Traceloop tool spans and respect entity content capture. Independently fall back to Mirascope 2.8.2 usage JSON fields with a 64 KiB UTF-8 bound and nonnegative integer validation. Shared tracing fixtures cover precedence, zeros, pricing, unknown names/values, content capture and malformed/oversized input; existing recorded cases are unchanged. The one-token-high streamed output from OpenLLMetry Anthropic instrumentation 0.63.0 is an upstream issue. Suppress a non-ERROR model-call ancestor only when a retained same-trace descendant model call carries a response ID or usage attributes, and either has a response ID or shares an exact response/request model name with an inclusive overlapping time window. The parent must have no response ID or the same response ID as that descendant; different response IDs keep both calls even when the model and time window match. A descendant without usage attributes and without a response ID never suppresses its richer parent; explicit zero token counts are usage evidence. An ERROR ancestor is suppressed only by an ERROR descendant sharing an exact model name and overlapping window; a successful fallback never hides its failure. Resolve retained evidence before its users and never use skipped calls as suppression evidence; suppression cycles retain a counted call. Suppress a non-ERROR OpenInference LLM prep span only when it has no usage attributes (zero/cache counts protect it), no response ID and no output, and a retained usage-bearing model span in the same interaction and trace starts between prep start minus 1 ms and interaction end, inclusive; its partner must be a sibling or unrelated span, never an ancestor or descendant. Failed or lone zero-usage spans still count. Shared fixtures cover ADK Go/anthropic-go nesting, deeper descendants, LlamaIndex 0.14.26/OpenInference 4.7.6 root siblings in both end orders, all guards, timing and immediate recording across processor/SDK flush and shutdown. Record every model call immediately with internal span evidence; apply nested and prep rules once in synchronous interaction End after finalizers, before pending events, totals, costs, breakdowns, primary model and answer selection. Preserve counted calls' original timing and already-published events, close skipped pending call indices, and count folded calls conservatively at the memory cap. Bound non-model ancestry and clear segment evidence after End or pause; serialize and validate internal span tags and resolved ancestors for pending calls across JSON pause/resume, without exporting them in events. Six lifecycle recording checkpoints change from zero to one; all existing expected-event arrays remain unchanged. Add a fixture retaining a usage parent with a same-model descendant lacking usage and a response ID. No schema change.

- **SDK-6902 — Pydantic AI span content — 2026-11-16.** Pydantic AI's instrumentation (default `include_content=True`) writes prompts, answers and instructions under its own attribute keys. Treat `pydantic_ai.all_messages`, `all_messages_events`, `final_result`, `tool_arguments`, `tool_response`, `pydantic_ai.tool.deferral.metadata`, `pydantic_ai.decision.state` / `questions` / `route_questions` / `answers`, `model_request_parameters`, `model_settings`, `embedding_settings` and `gen_ai.tool.definitions` as content keys, Mirascope's `mirascope.response.messages`, `mirascope.response.content`, `mirascope.trace.arg_values`, `mirascope.trace.output` and `mirascope.annotation.reasoning` as content keys too, and the generic `prompt` and `inputs` as content on spans from the `pydantic-ai` instrumentation scope only, and `error.message` on spans from Mirascope's `mirascope.llm` and `mirascope.ops` scopes only, masked like `exception.message`; Eve's `ai.response.tool_calls` as a content key, and `agent.session.title` and `agent.channel.delivery.input` on spans from the `eve.agent` scope only: removed with capture off, masked with capture on. `metadata` and `gen_ai.agent.description` are app-written and stay. Add `span-content-keys-v0.1.json`, the content lists every SDK asserts; the tracing conformance fixture covers stripping, masking and scope matching. No schema change.

- **SDK-6799 — wrapper and manual spans — 2026-11-13.** Opt-in `emitSpans` (Python `emit_spans`, Go `EmitSpans`) emits one `ai_otel_span` per logical provider wrapper request, independently of `emitLlmCalls`, with GenAI chat attributes and `rudderstack.span_source: "wrapper"`. Manual `span()` operations (`execute_tool`, `retrieval`, `invoke_agent`) use source `manual`, preserve callback return/error behavior and nest through async context; wrappers inherit the same parent. Internal W3C traces persist across pause/resume, independently of application trace links, without an interaction root span. Retained product call events carry the emitted span ID; overflow aggregates omit it. Google AFC has one chat span across all turns, joined only on the final response report. Content acquisition is independent of product publication, masked once; shared normalization strips nested bytes and cyclic edges and stringifies primitive Map keys. Add `emit-spans-v0.1.json` with portable clock, ID and container inputs and extend conformance/pause fixtures. Framework span emission and processor deduplication are outside this part; enabling the processor alongside wrapper spans can produce two spans for a call. No schema version change.

- **SDK-6798 — per-call content in the SDKs — 2026-11-12.** The SDKs now send `call_index` on every `ai_llm_response_received` and, with `emitLlmCalls` and `captureContent`, `input_messages`, `input_truncated`, `output_text` and `output_tool_calls` from all integrations, never carrying inline binary (byte arrays, `data:` URIs and base64 media payloads are removed). Shared fixture scenarios (`per_call_content` in `conformance-v0.4.json`, `perCallContent` cases in `tracing-product-events-v0.1.json`) fix the size-trim, media-part and sanitiser rules; pause snapshots carry an optional `call_sequence` and per-pending-call `call_index`. - **SDK-6819 — submit_feedback — 2026-11-12.** Add `mcp_feedback_submitted`, sent when the agent calls the injected `submit_feedback` tool (opt-in through the SDK's feedback option). - **SDK-6818 — structured content masking — 2026-11-12.** With content capture on, recursively mask every string in object and array content attributes at span, event, resource, instrumentation scope and link locations, keeping non-string leaves without mutating caller spans. - **SDK-6802 — tracing content privacy — 2026-11-12.** With content capture off, remove span status descriptions and `exception.message` / `exception.stacktrace` from exception events, keeping status codes, `exception.type` and other exception attributes. - **SDK-6797 — per-call content and wrapper spans — 2026-11-11.** Add optional `call_index` (integer >= 1, the 1-based call order within its interaction, always allowed and not content) and `span_id` (this call's `ai_otel_span` span ID when `emitSpans` is enabled, absent otherwise) to `ai_llm_response_received`. With both `emitLlmCalls` and `captureContent`, add `input_messages` (the full system prompt, history and tool results sent on the call, in the OpenTelemetry GenAI `gen_ai.input.messages` shape: an array of `{role, parts: [{type, content|...}]}`), `input_truncated` (true when messages were dropped or shortened), `output_text` and `output_tool_calls` (an array of `{name, arguments?}`, with required string `name` and any JSON arguments; GenAI-compatible naming where it does not conflict). Content is opt-in: treat as personal data and mask like `prompt_text`. Past the size cap, drop the oldest messages after the system prompt first.
  The new SDK option `emitSpans` (Python `emit_spans`, Go `EmitSpans`) makes wrappers and framework integrations emit `ai_otel_span` per model call, tool, retrieval and agent step, with GenAI semantic-convention attributes (`gen_ai.operation.name`: `chat`, `execute_tool`, `retrieval`, `invoke_agent`) plus `rudderstack.interaction_id`. Span content attributes follow `captureContent`. This is a spec contract for later SDK implementation. The changes are additive: no schema version bump; SDK `specVersion` stays `0.4.0`, and `ai_otel_span` schema v0.1 and its required fields remain unchanged.

- **SDK-5990 — server fields.** Answers support `blocked` with `block_reason`, app-set confidence, credits, agent versions, variants and compaction counts. - **SDK-5992 — sampling.** Optional per-event rates stamp kept server events with `sample_rate`, including `ai_limit_reached`. The shared SHA-256 interaction draw keeps decisions consistent across events and segments. Answers remain unsampled by default; the shared sampling fixture fixes cross-SDK decisions.
- **SDK-5991 — pause/resume.** Each paused or final answer segment shares the interaction ID. Paused segments carry `pause_reason`; final segments carry `pause_count` and `total_paused_ms`. JSON snapshots preserve scope, deduplication and pending usage across restarts. Optional `ai_task_started` reports new background runs once and is not repeated on resume.

The server schema and conformance fixture are v0.4; SDKs emit specVersion 0.4.0. The migration checker accepts both 0.3.0 and 0.4.0 captures. The client schema remains v0.2, matching the v0.3 release precedent. “Since v0.4” annotations remain: the v0.3 release did not remove version annotations.
