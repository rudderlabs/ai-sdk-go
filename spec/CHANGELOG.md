- **SDK-6799 part 3 — one span per call with the span processor — 2026-11-17.** The SDK span is the one sent when it has an analytics client and its mandatory core fits the span size budget with room for completion timing and status; otherwise OTel exports normally and SDK delivery follows its ordinary path. When RudderStack processors replace an OTel model span, the SDK span is the one kept; if the SDK's own client fails to deliver, that span is lost, as the call's product events are. An inner OTel model-call span with any active SDK call ancestor in the current interaction is dropped by every RudderStack processor using shared coverage across mixed presets and package copies. Manual tool/retrieval/agent middleware do not hide that ancestor, and ancestry stops at the interaction boundary; other processors receive it unchanged. The first direct wrapper call or integration chat span inside an observed, active, recording outer model-call span of the same open interaction adopts its trace/span/parent IDs, fixes the SDK trace (persisted through pause/JSON restore), and sends normally through the SDK path. Later direct calls are children of the adopted ID. A global replacement mark drops the OTel span synchronously at end across processors; there is no owner settlement, held fallback, direct/async owner export, owner timeout or shutdown coupling. SDK-specific limits, such as package copies and map caps, are in each SDK's tracing docs. Filters, batching and tracing-client failures cannot suppress the SDK call. An outer span without an SDK call exports normally; unsampled recording spans remain eligible. Streaming completion after OTel end retains the adopted IDs. Trade-off: RudderStack receives SDK attributes and call timing under OTel IDs, while APM receives the app's original span unchanged. Delayed Agents generation/response starts repoint reservations and unsent children only if none was sent; otherwise retain the reserved ID, clear replacement and export both spans with intact trees. Newer SDK spans in between, ended spans/interactions, other interactions, non-active tracers, model attributes added after start and the bare exporter cannot adopt. Extend `fixtures/span-dedup-v0.1.json` to fixture version 2 with `replaces`, ordered call IDs and delayed-parent cases. Covered OTel descendants retain their span IDs and tree under the SDK owner trace without changing APM spans or user callback inputs; keep an original OTel parent if a child already used it before coverage was committed. An SDK span that replaced or covered an OTel span follows the mandatory-core and ordered shedding rule in [SDK span delivery budget](fixtures/FIXTURE-FORMAT.md#sdk-span-delivery-budget). Spans-off output and event schemas are unchanged.

- **SDK-6111 — callback pause refusal — 2026-11-17.** Pause returns the existing not-paused value without mutating the interaction when called from its own SDK callback: error-hook kind `pause_refused`, reason `in_callback`. Error handlers, application code, and other interactions remain eligible. Python threads and Go goroutines wait for pricing (including retries/capture) for an internal 5 s bound, then refuse with reason `pricing_in_flight`; late credits stay in the open segment. Python loop-thread callers refuse immediately when a wait would block the loop; Node synchronous pricing cannot reach the wait path. Snapshots do not carry or restore in-flight pricing; callback pause refusal keeps pricing in the open segment. End continues to count retained in-flight revisions once without late credits. No schema change.

Unused aliases cannot invalidate restoration or change the saved interaction ID. - **SDK-6111 / SDK-6017 — call-merge, pause and overflow edge cases — 2026-11-16.** Pause refuses calls from the same interaction's SDK callback on the same caller, returning the not-paused value without changing the interaction and reporting `pause_refused` with reason `in_callback`. Error handlers, application code and callbacks for other interactions may pause. Other Python threads and Go goroutines wait for all pricing attempts, including retries and capture repricing, for an internal, nonconfigurable **5-second** bound; expiry refuses with reason `pricing_in_flight`, leaving late credits in the open segment. Python event-loop callers refuse immediately if waiting would block the loop; Node's synchronous pricing cannot reach the wait path. Snapshots do not carry or restore in-flight pricing. End does not wait: retained calls count once without an in-flight revision's late credits.

  Pause settles pending call/tool events before capturing totals: writes accepted during those delivery passes count once in the paused segment, with their own events; writes accepted after capture remain pending for resume. Final End refuses writes during delivery and all writes after End. Pause freezes its filtered answer before tool-event delivery and response redaction, so callbacks and redactor-created tools cannot replace it. If span filtering removes its source call, the retained span's answer replaces it and is redacted as usual. Each call-delivery pass emits every call pending at its start before filtering spans added during that pass for the next pass. Already-emitted parents retain their counts and frozen answers; filtering reindexes retained first-report positions so late twins cannot promote an older primary model.

  Calls folded past `maxCallsPerInteraction` include `cost_usd`, `credits` and `server_tool_cost_usd` only when every successful report folded into it had one, and omit `error_type` if any report succeeded. Same-source repeats remain repeats. Metadata enrichment reprices retained usage, raw model ID, cost and status with the merged agent, purpose, fallback and BYOK flags; unchanged metadata does not invoke the hook. Report-supplied credits remain authoritative. A span twin does not reprice explicit credits unless its usage replaces the twin's. Aggregate tracing twins retaining wrapper usage also retain its agent, purpose, fallback and BYOK metadata for pricing, regardless of arrival order or resume path. Changed flags on repeats update retained calls and pending events in both directions. Cancelled retained calls cannot acquire credits from enrichment in the current segment or after either resume path; failed-call enrichment preserves retained amounts. Legacy pending calls with credits and no `credits_explicit` marker keep those report-supplied credits.

  Enrichment is visible before pricing. Each call versions its pricing basis, including twin merges: re-entrant or concurrent enrichment cannot publish an older hook result over newer usage, metadata or credits, even when earlier values compare equal. Superseded pricing retries the newest retained basis up to three attempts, then omits credits and reports `credits_unstable`. Call events, response totals and snapshots publish credits with the usage and metadata that were priced. Hooks must be side-effect free and idempotent because one call can invoke them repeatedly. Go isolates every pointer passed to credits hooks and reprices authoritative twins sharing response IDs. A wrapper report and a span naming a dated ID of the same non-Claude model (`gpt-4o`, `gpt-4o-2024-08-06`) merge into one call; another model in the family (`gpt-4o-mini`) does not.

  A malformed `pending_calls` or `pending_tools` field invalidates the snapshot: all SDKs warn and start a fresh interaction; absent optional pending fields must be omitted, since JSON null is malformed. Python also warns and starts fresh on any snapshot-reading exception. Canonical keys take precedence over legacy aliases, including canonical null values; unused aliases cannot invalidate restoration or change the interaction ID. Node reads only recognized pending-record keys, leaving unused extension getters unevaluated. All SDKs write top-level `primary` and `outcome_hint` objects and accept legacy Python positional lists, preserving model/provider overrides, persistence and outcome ordering. Pending records share `matched`, `usage_known`, `started_at` and `ended_at`; readers also accept Go's `twin_matched`, `usage_unknown` and `uncredited`, and Python's `started_ns` / `ended_ns`. All readers accept epoch-millisecond numbers and RFC3339 text. Timestamp writing is staged: Node/Python write epoch milliseconds; Go writes RFC3339Nano UTC text until released Go readers accept numbers. Unparseable timestamps invalidate restoration, subject to the [known limits and timestamp downgrade limits](PAUSE-RESUME.md#known-limits) in [PAUSE-RESUME.md](PAUSE-RESUME.md).

  Pending calls preserve `raw_model` for deployed-ID pricing (falling back to `model` for legacy records) and optional boolean `credits_explicit`. An unsent folded-call event is stored as a `history_only` record with `call_event_pending` and neither `last` nor `last_ok`, and emits after restoration without adding totals. Optional one-based `report_sequence` preserves first-report order independently of aggregate call counts; Python and Go reconstruct legacy order from records, including intervening reports, so late twins cannot promote older primary models. Restored fractional `latency_ms` and `time_to_first_token_ms` round half up at emission, matching live call-window timing.

  Claude Agent SDK alias rows order groups by first-seen deployed model ID, then first-seen group within that ID, with main-loop groups last. Assistant IDs remain seen across results of one stream, so later aliases retain their deployed IDs and are not dropped as internal calls. Turn-level extras (1-hour cache writes, service tier and server tool counts) are allocated across every main-loop deployed-ID row; resumed provider hints are keyed by deployed ID, and standalone results report each dated row under its own ID. A `modelUsage` key or subagent `resolvedModel` maps to an assistant-seen ID only when it is an alias or names the same snapshot. Another dated ID keeps its own calls, tokens, cost and credits. Only assistant messages identify API model IDs; Python's `calls_by_model` keys follow `model_usage` keys, as in Node, and subagent results do not establish assistant IDs. Python `record_claude_result(primary_model=...)` with a family name retains each dated row's ID and assigns `num_turns` to that family's costliest row. Consumer-injected cancellation (`CancelledError` / `AbortError`) through `throw` / `athrow` reports `cancelled`; other injected exceptions report `app_error`. Provider iteration failures retain provider classification, and original exceptions are re-raised unchanged.

  SDK-6942 normalizes native content in mutable/frozen dataclasses, namespaces, inherited slots and object dictionaries, and Pydantic v1/v2 models. Python serializes Pydantic models through Pydantic on both the spans-on and spans-off paths: `model_dump(mode="json")` for v2 and JSON serialization for v1-style models. `Field(exclude=True)` values are omitted and `SecretStr` / `SecretBytes` values are masked. On main, with spans on, excluded fields and `SecretStr` values reached events; this fixes a released leak. Native bytes are removed before serializers can stringify or base64-encode them, except in Go custom-marshaler output with spans off (SDK-6948). On that path Go uses a value's `json.Marshaler` or `encoding.TextMarshaler` and strips its output as plain data; bytes encoded as ordinary text, including base64, can reach content (the accepted SDK-6948 trade-off). Other Go values and all Go values with spans on are walked field by field, retaining trusted time serialization.

  Shared fixtures cover pause segments, final-credit totals, JSON handoff, repeated pauses, standalone Claude normalization, explicit credits, cross-SDK snapshots, fractional timing and native containers in per-call content and span attributes/events, including cycles and nested collections. See [PAUSE-RESUME.md](PAUSE-RESUME.md#known-limits) for known snapshot and Go pricing limits. When a span and a wrapper report merge, the kept call's cost and credits are computed from the usage that is kept, or omitted when they cannot be, and a failed report stays failed when its twin has no status. With the rudderotel span processor, released Go reported a caller-cancelled Anthropic request or stream as successful and billed the cancelled stream; both are now cancelled calls without credits. Python captures Pydantic models through model_dump in python mode with raw bytes stripped; text that an app's own serializer returns, such as base64 or hex, is sent as is. A failed call never carries cost_usd or credits derived from its twin's usage or from the credits hook; only amounts the provider itself reported are kept. No schema change.
